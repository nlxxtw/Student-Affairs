# 数智学工

数智学工是运行在 Windows 本机浏览器中的学生工作管理系统。学生数据、附件、配置、日志和备份均保存在本机；除用户主动启用的在线 AI 功能外，日常业务功能不依赖网络。

## 快速开始

Windows 10/11：双击根目录的 `启动数智学工.vbs`，系统会在后台启动并自动打开工作台网页。需要停止本机服务时，双击同目录的 `关闭数智学工.vbs`。程序主体、数据、附件与备份均位于同级的 `数智学工数据/` 文件夹；无需直接操作内部 PowerShell 脚本。使用完毕直接关闭浏览器即可，本机服务会在后台保留，下一次双击会直接打开；重启电脑后会自动结束。

程序会在 `http://127.0.0.1:18766/login.html` 启动本机服务并打开欢迎页。在欢迎页点击「进入工作台」即可进入系统，无需设置密码；会话不按空闲或累计使用时长自动退出；退出、服务重启或相关账号/设备失效后需要重新进入。

请勿直接打开 `index.html`：页面需要本机服务提供登录、数据、附件、备份和安全会话能力。

## 运行要求

- Windows 10/11：建议使用 Microsoft Edge 或 Chrome；项目已携带 `runtime/node.exe`，无需另行安装 Node.js。
- 学业预警 Word/PDF 预览与下载依赖本机 Microsoft Word；未安装时不影响其他功能。
- 在线 AI 功能需要网络以及用户自行配置的模型服务和 API Key；未配置或禁用 AI 时，其他本地功能正常可用。

| `启动数智学工.vbs` | 根目录启动入口；双击后启动同级 `数智学工数据/` 中的工作台 |

| `data/` | SQLite 数据库、附件、日志和运行时 PID；包含真实数据，不应纳入发行包 |
| `backups/` | 手动备份、恢复前保护备份和 WebDAV 上传快照 |
| `runtime/` | 随系统分发的 Node.js 运行时 |

`.workbuddy/` 仅为协作工具的项目记忆和操作记录，不参与程序运行；删除它不会影响系统功能，但会丢失协作历史。

字段管理仅保留在“学生信息管理”和“个人发展”两个导航分组：学生管理、班级干部管理、宿舍管理及成长档案页面顶部的“字段扩展”提供“字段管理”和“查看/填写字段”。字段管理会完整列出该模块已有的系统字段（只读、不可删除）和自定义字段；可新增单行文字、多行文字、数字、日期、下拉选项字段，调整名称、顺序和选项。“停用”相当于安全删除，历史记录与备份仍保留原值。已有记录在字段台账中填写，编辑时可展开核对该条记录的系统字段和值，并可按记录 ID 使用字段映射导入或导出自定义字段；原有系统字段、必填校验和原模块表单/导出结构不受此设置改动。其他业务模块不再提供字段管理入口，旧字段配置和旧字段值会在加载时清理。

宿舍管理以“公寓资源”为区位、楼栋、房间和床位的唯一维护入口；住宿分布仍以学生管理中的当前在校生为名单来源。校内住宿必须完整填写宿舍楼、房间号和床位号，同一床位不能分配给两名学生。学生转为毕业时系统确认后自动退宿并释放床位，入住历史继续保留；床位独立登记只作其他学生情况备注，不修改学生档案，也不计入入住人数、空床或冲突统计。

## 数据、备份与日志

- 正式数据库：`data/workbench.db`（SQLite）。
- 附件：`data/attachments/`；单个附件上限为 100 MB，默认总配额为 2 GB。
- 备份：`backups/`；支持手动备份及操作前保护快照。局域网开启后，每个北京时间自然日首次成功数据操作约5秒后自动备份数据库与附件；没有固定时刻定时备份或周期弹窗提醒。
- 日志：`data/server.log`、`data/server-error.log`；默认单个日志文件达到 2 MB 时轮转。

不要手工修改正在使用的 SQLite 数据库。涉及恢复、清理附件或数据覆盖时，优先通过系统中的“数据备份”功能完成，并先创建可验证的备份。

## WebDAV 私有云备份

“数据备份与 WebDAV 私有云”页面支持坚果云、Nextcloud、群晖等标准 WebDAV 服务。它用于**单人加密备份和换机恢复**，不是多人实时协作功能：同一时刻只应在一台设备编辑数据。

- WebDAV 地址必须使用 HTTPS；请使用服务商生成的应用授权码，而非网页登录密码。
- 地址、账号与授权码仅保存在本机服务端的加密数据库中，浏览器不会保存或展示授权码。
- 每次上传前系统创建一致性本机快照，并将数据库、附件及便携数据密钥封装为由“同步加密密码”保护的 `.szwd` 文件；该密码不保存，恢复时必须重新输入。
- 云端恢复会先创建本机保护备份，再完整替换当前数据。请先保留两端本机备份，避免把并发修改相互覆盖。

换电脑时，先双击 `关闭数智学工.vbs` 停止服务，再完整复制整个数智学工文件夹（包括根目录的启动/关闭 VBS 与完整的 `数智学工数据/` 文件夹）到新电脑。`数智学工数据/data/portable-data-key.json` 是数据读取所需的便携密钥，不能遗漏、单独删除或上传至公共位置。已使用旧版密码登录的历史副本，升级后首次打开会要求输入一次原密码以转换；转换完成后不再需要密码。

## 数据导入约束

### 四步导入向导（V2.1.0）

学生管理、资助情况、住宿信息、综测数据、就业意向答卷，以及课堂管理、班会/活动、党团员发展、谈心谈话、心理预警、家校联系、突发事件、查课、查寝和帮扶记录的 Excel/CSV 导入，统一使用四步流程。学业预警会先选择“预警名单”或“课程明细”，随后分别进入同一四步流程：

1. 选择导入文件。
2. 确认导入信息与数据预览。
3. 字段映射：左列“系统字段”固定，右列“Excel 列（表头）”从本次文件表头中选择。
4. 校验并导入：问题行不写入，确认后才写入通过校验的记录。

映射必须覆盖必填系统字段，且同一 Excel 表头不能重复映射。新增表格导入入口时应复用 `openMappedImportWizard`，传入字段清单、必填字段、模块校验函数及写入函数；不要在上传后直接写入数据。

学生管理新增、编辑或导入学生时，已维护班级继续以基础数据中的学院、专业、年级等归属为准。遇到未维护的学院、专业、年级、班级或招生类别时，系统会列出缺失项并询问是否自动添加到“基础数据维护”；点击“是”后先建立完整层级，再保存学生。自动建立新班级时必须同时提供学院、专业和年级，层级冲突时停止写入并提示修正。

学籍状态是学生新增、编辑和导入的必填字段，只允许使用系统现有的在校、休学、退学、转出、毕业、延期毕业、其他七种内部值；界面继续使用“在校生”“转专业（转出）”“已毕业”等既有展示名称。历史空值按原有业务语义兼容为“在校”。

“实时课表”是位于“课堂管理”之后的独立可视化周视图，统一维护 `nnuzc_course_schedules`，供课堂管理和查课记录按学期、班级、日期自动匹配课程。课堂管理已移除“本学期课表”展示和维护卡片，保留课堂考勤记录与班级统计；已有课程数据不删除。独立课表页同步提供 AI 智能识别、PDF 识别、字段映射导入和课表模板四个既有导入入口，并支持学期、班级、周次筛选，实时课程状态、手动排课、动态增删每节课作息时间、班级课表清空、当前周课表导出，以及跳转课堂考勤登记。课表的开学日期、总教学周数直接读取“学期设置”，课表页面不再提供重复的校历编辑入口。

周课表按课程类别区分卡片颜色，跨多个节次的课程只在起始节次分组显示一次。“全部班级”模式下，同一时间格默认显示前 4 门课程并提供展开入口，避免课程密集时无限拉高整行；选择具体班级后完整显示该班课程。

所有携带“学号”列、且归属于既有学生的业务数据导入，必须先验证学号是否存在于学生管理主表（`nnuzc_students`）。学号不存在时应明确提示并阻止写入，避免产生孤立记录。

综合测评与学业预警属于按学期导入的学籍数据集，可允许导入文件中的学生记录独立存在，但必须向用户明确提示。这两个例外不能扩展到其他按学号关联学生的业务模块。
